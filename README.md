# AgentMesh

로컬 LLM과 클라우드 에이전트를 함께 사용하는 작업 환경의 **구조와 운영 규칙**을 정리하는 저장소입니다.

목표는 빠른 응답, 필요한 만큼의 모델 사용, 검증된 결과입니다. **이 저장소는 설계 문서이며 실행 앱이나 자동 연동 설정을 포함하지 않습니다.** 아래 구조는 실제 연결 상태나 측정된 성능을 뜻하지 않습니다.

## 작업 환경 구조

![OMP → 로컬 라우터 → 로컬 모델 또는 클라우드 에이전트 → 검증 → OMP 반환. 검증 실패 시 라우터로 돌아가 재작업하는 애니메이션 구조도](docs/traffic-flow.gif)

버튼 없이 자동 반복되는 **1600×960 · 50fps** GIF입니다. 프레임 간격은 20ms이며, 한 주기는 31.4초입니다. 이는 이미지의 재생 사양으로 모델 응답 속도나 모니터 주사율을 뜻하지 않습니다. 실제 재생 속도는 뷰어와 기기에 따라 달라질 수 있습니다.

왼쪽에서 요청을 받고, 가운데에서 로컬 처리 또는 클라우드 위임을 거쳐, 오른쪽에서 결과를 검증합니다. 위쪽 연결선은 검증 실패에 따른 재작업, 아래쪽 연결선은 검증 통과 후 OMP로의 반환입니다.

간단한 응답 → 긴 문맥 분석 → 코드 구현 → 설계와 추론 → 실패 후 재작업 순서로 다섯 가지 예시를 보여줍니다. 현재 경로와 담당 노드가 강조되고 하단에 작업명과 진행 단계가 표시됩니다. 움직임을 보지 않아도 아래 표에서 같은 흐름을 읽을 수 있습니다.

## 구성요소와 책임

| 구성요소 | 역할 |
| --- | --- |
| OMP | 사용자 요청·제약·완료 조건을 접수하고 진행 상태와 최종 결과를 반환 |
| 로컬 라우터 | 작업 유형·복잡도·사용 가능한 모델을 기준으로 담당을 배정하고 재작업 경로 결정 |
| Qwen 4B | 빠른 분류, 간단한 질문, 짧은 요약 |
| Qwen 35B | 긴 문맥 분석, 요구사항 정리, 초안 생성 |
| Codex | 코드 구현, 수정, 테스트 작업 |
| Claude | 아키텍처 설계, 복잡한 추론과 검토 |
| 검증 | 완료 조건과 근거를 확인하고 통과·실패·미확인을 구분; 실패 근거를 라우터에 전달 |

OMP는 이 문서의 요청 진입점 역할명입니다. 검증은 별도의 모델명을 뜻하지 않으며 작업별 검사 절차를 나타냅니다. Qwen 4B와 Qwen 35B는 모델 역할을 나타내는 표시명이며, 정확한 배포판·양자화·실행 환경은 실제 환경에 맞춰 별도로 정합니다.

## 대표 요청 흐름

| 작업 | 흐름 |
| --- | --- |
| 간단한 응답 | OMP → 라우터 → Qwen 4B → 검증 → 결과 반환 |
| 긴 문맥 분석 | OMP → 라우터 → Qwen 4B 분류 → 라우터 → Qwen 35B → 검증 → 결과 반환 |
| 코드 구현 | OMP → 라우터 → Qwen 4B 분류 → 라우터 → Qwen 35B 문맥 정리 → Codex → 검증 → 결과 반환 |
| 설계 | OMP → 라우터 → Qwen 4B 분류 → 라우터 → Qwen 35B 문맥 정리 → Claude → 검증 → 결과 반환 |
| 재작업 | 검증 실패 → 라우터 → 담당 모델에 실패 근거와 기존 문맥 전달 → 수정 → 재검증 → 통과 시 결과 반환 |

분류와 문맥 정리가 이미 끝난 요청은 라우터에서 Qwen 35B, Codex 또는 Claude로 바로 배정할 수 있습니다. 구조도는 모든 조합 대신 대표 경로만 보여줍니다. 재작업 애니메이션은 코드 검증 실패 후 Qwen 35B → Codex로 인계하는 예시이며, 실제 수정 담당은 실패 원인에 따라 정합니다.

## 운영 원칙

- 가능한 작업은 로컬에서 처리합니다.
- 구현은 Codex, 복잡한 설계와 추론은 Claude에 위임합니다.
- 모델을 옮길 때 목표·문맥·제약·완료 조건을 함께 전달합니다.
- 결과를 검증하고, 실패하면 근거를 첨부해 재작업합니다. 미확인 결과를 통과로 취급하지 않습니다.
- 같은 실패가 반복되거나 정한 시간·비용·재시도 한도에 도달하면 접근을 바꾸거나 중단 사유를 반환합니다.
- 속도와 품질에 관한 판단은 실제 측정과 검증 결과를 기준으로 합니다.

담당 배정, 인계 항목, 검증과 중단 기준은 [운영 규칙](RULES.md)에서 관리합니다.
