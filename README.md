## 모델 선택

총괄은 고정하고 작업자는 파트별로 선택합니다. 아래는 권장 프로필이며 실제 연결·호출은 별도 검증합니다.

| 역할 / 프로필 | 모델 ID | 추론 설정 | 배정 대상 |
|---|---|---|---|
| **OMP 현재 모델 · default · 총괄** | **`claude-opus-5-5`** | **high 고정** | 요청 분해, 의존성·담당·완료 조건 결정, 결과 통합·재배정 |
| 구현 기본 | `gpt-6.1-sol` | medium | 범위가 명확한 기능 구현·버그 수정·테스트 |
| 구현 심화 | `gpt-6.1-sol` | high | 다중 모듈 변경·큰 리팩터링·원인 추적 |
| 난제 대응 | `gpt-6-astra` | high; 복합 가설 검증은 xhigh | 근거 있는 재시도에도 풀리지 않는 구현·분석 |
| 설계·문서 기본 | `claude-sonnet-5-5` | medium | 파트별 설계·UI/UX·한국어 문서 |
| 설계·문서 심화 | `claude-sonnet-5-5` | high | 상충 조건·큰 영향 범위·세부 일관성 검토 |
| 로컬 수정·분석 | `Qwen3.6-35B-A3B` · MLX 4bit | Thinking on | 범위가 확정된 소규모 수정·자료 분석; 수정 위치·영향 범위·검사 방법 사전 확정 |

Qwen3.5-4B는 기본 구성에서 제외합니다. 모델 ID는 공급자별 실제 식별자에 연결하며, 미등록 작업자가 총괄 모델을 상속하지 않게 합니다. Qwen의 Thinking·서버 추론 예산은 클라우드 effort 등급과 구분합니다.

설정 근거: [Claude effort](https://platform.claude.com/docs/en/build-with-claude/effort) · [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol) · [GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra) · [Qwen3.6](https://huggingface.co/Qwen/Qwen3.6-35B-A3B) · [OMP 작업자 연결](https://github.com/can1357/oh-my-pi/blob/main/docs/task-agent-discovery.md)

## 분해·배정 기준

| 판단 항목 | 적용 기준 |
|---|---|
| 작업 경계 | 프롬프트 개수가 아닌 산출물·완료 조건 단위로 분해; 한 요청에 여러 담당 배정 가능 |
| 로컬 우선 후보 | 요구사항·수정 위치·영향 범위·검사 방법이 모두 확정된 소규모 수정·분석; 파일 수·요청 길이만으로 판정하지 않음 |
| 로컬 예시 | 버튼 문구, 한정된 화면의 간격·표시 위치, 차트 기본값, 정해진 형식의 자료 추출·분류 |
| 클라우드 우선 | 인증·권한·계정 경계, 저장 형식·마이그레이션, 동시성, 모듈 간 동기화, 게이트웨이·배포 또는 원인 불명 오류 |
| 담당 선택 | 로컬 기준을 충족하는 파트는 로컬 수정·분석; 그 밖의 코드 변경·재현·실행 검사는 구현 프로필; 설계 대안·문서 구성은 설계 프로필 |
| 로컬 중단·전환 | 범위를 벗어난 변경 필요, 숨은 의존성, 원인 불명 검사 실패 또는 메모리 부족이면 중단·근거 반환; 총괄이 클라우드 프로필로 재배정 |
| 실행 순서 | 필요한 입력 산출물이 없으면 대기; 서로 독립인 파트만 병렬 실행 |
| 편집 충돌 | 동일 파일·공유 상태를 수정하는 작업은 직렬화하거나 격리 후 병합 |
| 모델·강도 | 명확한 파트는 기본 프로필; 불확실성·영향 범위·검증 난도가 크면 심화 프로필 |
| 난제 전환 | 실패 원인·시도 결과를 확인하고 접근 변경이 필요할 때 상위 프로필 선택; 무조건 승급 금지 |
| 사용자 제약 | 지정 담당·외부 전송 제한·시간/비용 한도 우선; 총괄에 전달할 원문도 전송 제한 적용 |
| 통합 | 총괄이 파트 간 인터페이스·요구사항 누락·상충 결과를 확인; 실제 검사 근거와 함께 반환 |

## 작업 계약

| 항목 | 필수 내용 |
|---|---|
| 작업 단위 | 작업 ID, 원문 중 담당 범위, 공통 목표·제약, 담당 프로필, 선행 작업 ID, 산출물·완료 조건 |
| 문맥 전달 | 담당 파트와 필요한 파일·자료·선행 결과만 전달; 공통 제약 보존; 요약으로 원문 의미 대체 금지 |
| 결과 수신 | 작업 ID별 결과·변경 파일·검사 근거·미해결 항목 수집; 선행 작업 통과 후 후속 작업 해제 |
| 로컬 변경 검증 | 허용 파일·변경 범위 확인, 관련 테스트·문서 일치 검사; UI는 실제 화면 확인; 검사 불가 항목은 미확인으로 반환 |
| 완료 판정 | 파트별 검사와 통합 검사 모두 충족해야 완료; 실패·미확인은 별도 표시 |
| 재작업 | 실패한 파트와 영향받는 후속 파트만 재배정; 기존 성공 결과·사용량·실패 이력 유지 |
| 실행 관리 | OMP와 연결 코드가 호출·대기·동시 실행·결과 수집·한도 적용; 총괄의 계획만으로 실행 완료 처리 금지 |
| 로컬 메모리 | 35B 필요 시 로드, 로컬 추론 동시 실행 1부터 검증; OS·개발 도구·문맥 캐시 포함해 판단 |
